# OpenWA, as A7 runs it

Upstream is [rmyndharis/OpenWA](https://github.com/rmyndharis/OpenWA) — MIT, a
self-hosted WhatsApp API gateway with a bundled dashboard. This folder is that
project's source at the commit we deployed, **with two local changes**, so it can
be edited here and rebuilt rather than pulled blind on the server.

It is the QR-linked channel: personal numbers linked by scanning, the same job
`wa-qr/` does. **It has nothing to do with the WABA side.** `backend/` and the
alots.io gateway are untouched by anything in here.

## Before you change anything here

Three things that have already cost time, and one that would cost a lot more:

- **Do not reformat this source.** It is vendored upstream. A `sed` meant to drop
  a single import once stripped every blank line in `Layout.tsx` — valid
  TypeScript, and it turned the diff against upstream into the entire file. Use
  targeted edits and keep the diff small enough to read.
- **The plugin system stays.** The whatsapp-web.js engine is itself loaded through
  it (`[whatsapp-web.js] WhatsApp-web.js engine plugin loaded` on boot). Removing
  the system takes WhatsApp with it. The Plugins *page* is a different thing and
  is already gone.
- **Roles and per-agent scoping already exist — do not build them again.**
  `ApiKeyRole` is `admin`/`operator`/`viewer` and `allowedSessions` confines a key
  to named sessions; both are enforced server-side, in
  `src/common/security/session-scope.ts`. An agent is an `operator` key whose
  `allowedSessions` lists their numbers.
- **Page CSS arrives as a route chunk, after `index.css`.** So source order
  favours upstream and an override wins only on specificity. `a7-embedded.css`
  hangs everything off `:root[data-embedded]` for exactly that reason — drop the
  prefix and the rule loses silently.

## What is different from upstream

Everything not listed below is upstream, byte for byte.

**`src/main.ts` — who may frame the dashboard.** helmet defaults to
`frame-ancestors 'self'` and sends `X-Frame-Options: SAMEORIGIN`. The dashboard is
opened inside the A7 panel, which Bitrix frames in turn, and both headers refuse
that with a blank frame and nothing on screen to say why. The patch reads the
allowed embedders from `FRAME_ANCESTORS` and drops `X-Frame-Options` only when
that variable is set — unset, upstream behaviour is unchanged.

The rest of the policy is deliberately left alone. Stripping the whole CSP at the
proxy would have been one line of nginx and would also have thrown away the
per-request script nonce and `default-src 'self'`, on the one service in the
building that holds live WhatsApp sessions.

`a7/patch_frame_ancestors.py` re-applies it. It is idempotent, and it refuses
rather than guesses if upstream has moved the code it anchors on — so after
pulling an update, run it and read what it says.

**`docker-compose.override.yml` — the Docker socket proxy is off.** Upstream ships
`docker-proxy`, which lets the dashboard create datastore containers. Its own
`SECURITY.md` says the proxy cannot scope container-create payloads, so a
compromised API container could create containers with host bind-mounts. This host
also runs the live A7 stack, so that is not a trade worth making for a convenience
we do not use. `DockerService` degrades gracefully and logs
`Docker not available`.

The override is also where a variable gets forwarded into the container.
`docker-compose.yml` forwards an explicit list, and anything missing from it never
arrives however it is set in `.env` — `FRAME_ANCESTORS` is there for that reason.

**`dashboard/src/main.tsx` + `a7-embedded.css` — how it looks when framed.**
`main.tsx` puts `data-embedded` on the document when the page is not the top
window; the stylesheet keys off it. Framed, the page loses its own padding, its
title and its strapline — the panel's bar above already says "Linked devices" —
and `.chats-layout` stops being pinned to `calc(100vh - 12rem)`. That allowance is
upstream leaving room for the page heading, and **inside a frame `100vh` is the
frame**, so it came out of the height a second time and sat along the bottom as a
dead strip. Standalone is untouched, which matters: that is how the dashboard is
reached over an SSH tunnel when Bitrix is not involved.

**Branding.** `appName` in all twelve locales, the document title, and the logo in
its three places — both sidebar states and the login card — are A7's, and
`a7-logo.png` is the favicon too. `openwa_logo.webp` and the old `favicon.svg` are
deleted rather than orphaned. The author credit in the login footer is
deliberately left alone: renaming what we deploy is one thing, taking someone's
name off their work is another, and their licence is why this can be vendored at
all.

**`dashboard/src/components/Layout.tsx` — the menu.** Every nav item except Chats
is `adminOnly`. An agent sees one link. This is the menu, not the lock: what an
agent can actually reach is decided by their key's `role` and `allowedSessions`,
server-side. Hiding a link only stops it being clicked.

**`dashboard/src/components/chats/ChatSidebar.tsx` — no Chats/Channels/Status
tabs.** A7 uses neither channels nor statuses, and the bar was two thirds of a
switch with one useful position. The lists below still key off `activeTab`, which
nothing can now move off `'chats'`; they are left in place rather than deleted so
an upstream merge stays readable.

**`dashboard/src/App.tsx` — the Plugins page is not routed.** See above for why
the system behind it stays.

## Running it

```bash
cp .env.a7.example .env          # then fill in API_MASTER_KEY
docker compose build             # no service argument
docker compose up -d
```

`.env` is gitignored and holds the dashboard login. `data/` is gitignored too and
holds the linked sessions — a phone's session is a credential, not a cache.

## How it is reached

The app binds `127.0.0.1:2785` only; it is not on the internet by itself. nginx
publishes it on **port 2786** of `wa.srv1802669.hstgr.cloud`, reusing the
certificate already issued for that name — see `a7/nginx-a7-openwa.conf`.

A separate port rather than a path, because the dashboard is a single-page app
that asks for `/assets/...` and `/api/...` absolutely. `/api/` on the main host
already belongs to Django and that collision cannot be proxied around. A separate
hostname would have needed a DNS record and a second certificate.

Every request passes `auth_request` against the panel's own session first, the
same gate that stands in front of `/qr/`. OpenWA does have a login, unlike wa-qr,
but it is one shared API key — thin on its own between the open internet and an
account that can read every conversation the company has. Verified: `401` without
a panel session, `200` with.

## Still true, and worth knowing

- The API key the app mints on first boot is **printed in the container log**.
- One shared key means every agent who reaches the dashboard uses the same
  credential. There is no per-agent identity in it, and nothing records who did
  what — which the A7 panel does have.
- Upstream is unofficial and reverse-engineered. A linked number can be banned,
  and no appeal exists. `SEND_PACING_ENABLED` and the warm-up schedule are the
  built-in guards; neither is on here yet.
