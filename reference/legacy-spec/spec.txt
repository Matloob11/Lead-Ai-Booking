1. Executive Summary -- What We Are Building and Why

This document describes a single, connected system that lets A7 Group agents talk to customers on WhatsApp using
the company's own number -- never their personal number -- while the company keeps full control and visibility of
every conversation.
Today, agents pull leads out of Bitrix24, message customers from their personal WhatsApp, and close deals privately.
Management cannot see what was said, cannot protect the lead, and cannot stop an agent from taking the client with
them if they leave. This system closes that gap completely.

The one-line goal

  Goal
  Every customer conversation happens on the COMPANY WhatsApp number, is visible to management in real time, is
  logged automatically into Bitrix24, and works from an agent's phone while they are out doing viewings -- with no
  laptop required.

What the agent experiences

  · One app. A simple app on their phone (like a normal chat app) that shows their assigned customer chats.
  · Chat normally. They tap a customer, type, and send -- the message goes out from the company WhatsApp

      number.
  · One-tap re-open. If the 24-hour window is closed, one button sends an approved template to re-open the chat.
  · No personal number. They never see or use their personal WhatsApp for company customers.

What the manager (you) experiences

  · See everything. A live dashboard showing every agent's conversations as they happen.
  · Smart alerts. Automatic flags: serious buyer, competitor agent, duplicate client, poor agent behaviour.
  · One source of truth. Everything already sitting inside / linked to Bitrix24 -- no double data entry.

3. System Architecture (The Big Picture)

The system has five moving parts. Everything is glued together by one central Backend Server that A7 Group owns
and controls.

The five parts

  · 1) WhatsApp Cloud API. Meta's WhatsApp Business Cloud API -- already owned by A7 Group. Sends and
      receives the actual WhatsApp messages.

  · 2) Backend Server. A Node.js server that receives every incoming message (webhook), stores it, applies the AI +
      detection logic, and pushes it to the app, dashboard and Bitrix24. This is the brain.

  · 3) Agent Mobile App. The phone app agents use in the field. It talks ONLY to the Backend Server, never directly
      to Meta.

  · 4) Manager Dashboard. A web dashboard for you and sales managers to watch and control everything.
  · 5) Bitrix24 + n8n. Already owned. The backend writes contacts, deals and chat history into Bitrix24 so the CRM

      stays the record of truth. n8n handles the automation glue.

How a message travels (incoming)

  1. Customer sends a WhatsApp message to the company number.
  2. Meta forwards it to the Backend Server via webhook.
  3. Backend saves the message, checks: is this number a known competitor agent? Is this client already talking to

      another agent? What is the AI sentiment?
  4. Backend pushes the message + flags to the assigned agent's app and to the Manager Dashboard in real time.
  5. Backend writes/updates the contact and chat in Bitrix24.

How a message travels (outgoing)

  6. Agent types a reply in the app (or taps a template button).
  7. App sends it to the Backend Server.
  8. Backend checks the 24-hour window: if open, send free-form; if closed, send an approved template.
  9. Backend calls Meta's WhatsApp API to deliver the message from the company number.
  10. Backend logs the outgoing message to the database, dashboard and Bitrix24.

  Key design rule
  The Agent App NEVER connects directly to Meta or holds any WhatsApp API key. It only talks to our Backend Server.
  This is what keeps the company in full control and stops any agent from taking the number or the data with them.

4. Component 1 -- WhatsApp Business API Layer

A7 Group already has WhatsApp Business API access. This section tells the engineer exactly how to wire it into the
Backend Server.

4.1 What must be in place

  · A verified Meta Business account and a WhatsApp Business API phone number (already owned).
  · A permanent System User access token (not a temporary token) so the connection never expires.
  · A registered Webhook URL pointing to our Backend Server, subscribed to 'messages' events.
  · Pre-approved message templates in the Meta Business Manager (see Section 6).

4.2 Receiving messages (Webhook)

The Backend exposes one public HTTPS endpoint, e.g. /webhook/whatsapp. Meta sends a GET request once to verify
it (echo the challenge token), then POSTs every incoming message to it.

For each incoming message the backend must capture: sender phone number, message text/media, timestamp, and
the WhatsApp message ID. Store it, then run the detection pipeline (Sections 8, 10, 11).

4.3 Sending messages

The backend sends messages by calling Meta's Cloud API endpoint /{phone-number-id}/messages with the company
token. Two message types matter:

  · Session message. Free-form text -- allowed only inside the open 24-hour window.
  · Template message. Pre-approved template -- required to start a chat or re-open a chat after 24 hours.

  Security note for the engineer
  The WhatsApp token lives ONLY on the Backend Server, stored as an environment variable / secret. It is never shipped
  inside the mobile app or the dashboard code. If it ever leaks, rotate it immediately in Meta Business Manager.

6. Component 3 -- The 24-Hour Window & Template System

This is the single most important feature for adoption. If agents find it hard to message a customer after a day or two,
they will go back to personal WhatsApp. This must be effortless.

6.1 How WhatsApp's rule works

  · When a customer messages you, a 24-hour 'service window' opens. Inside it you can send any free-form
      message for free.

  · After 24 hours of customer silence, the window closes. You can then only reach them with a pre-approved
      TEMPLATE message.

  · A7 Group's reality: customers often go quiet for 2-3 days while the team finds the right property, then the agent
      needs to re-open the chat. This is normal and must be one tap.

6.2 What the system does automatically

  11. The backend tracks, per customer, the time of their last inbound message.
  12. The app shows a clear status: green 'Open -- reply freely' or grey 'Closed -- send a template to re-open'.
  13. When closed, the agent taps one template from a ready list; the backend sends the approved Meta template

      with the customer's name filled in.
  14. The customer replies  the 24-hour window re-opens  the agent chats freely again.

6.3 Templates to pre-approve in Meta (starting set)

Template name     Purpose                                                 Category

welcome_intro     First contact / greeting a new lead.                    Marketing / Utility
property_ready    'We found properties matching your needs' re-open.      Utility

follow_up         Gentle follow-up after silence.                         Utility
viewing_confirm   Confirm a viewing date/time.                            Utility

document_request  Ask for documents (Emirates ID, etc.).                  Utility

Each template should have 2-3 rotating versions (worded differently) to stay compliant with anti-spam rules -- the

same pattern already used in A7 Group's owner-outreach packs.

Adoption is the whole game
If this feature takes more than ONE tap, agents will abandon the system. Build the template menu to be instant, pre-
filled with the customer's name, and impossible to get wrong.

7. Component 4 -- Bitrix24 Two-Way Sync

Bitrix24 stays the company's record of truth. The agent never has to enter anything twice -- the backend keeps
Bitrix24 updated automatically.

7.1 What syncs into Bitrix24

  · Contacts. Every new customer becomes / updates a Contact in Bitrix24.
  · Chat history. Every conversation is attached to that contact (as timeline/chat history or a linked deal).
  · Flags & scores. AI sentiment score, competitor-agent flag, and duplicate flag are written to custom fields on the

      contact.
  · Deals. Serious leads can auto-create or move a Deal in the sales pipeline.

7.2 How it connects

The backend uses the Bitrix24 REST API (inbound webhook) already available on A7 Group's on-premise Bitrix24. n8n
can handle much of this glue: backend fires an event  n8n workflow  Bitrix24 action. This keeps heavy CRM logic
out of the core code and easy to change later.

Custom fields to add in Bitrix24: Sentiment Score, Lead Status (Hot/Warm/Cold), Is Competitor Agent (Y/N), Duplicate
Alert (Y/N), Assigned Agent, Last WhatsApp Contact.

8. Component 5 -- AI Sentiment & Serious-Lead Detection

AI reads each conversation and tells you which customers are serious, so agents and managers focus energy where it
matters.

8.1 What the AI decides                     Meaning
                                            The customer's mood and interest level.
 Signal                                     How likely this is a real, ready buyer/tenant vs a time-waster.
 Sentiment (positive / neutral / negative)  A simple label managers can act on instantly.
 Seriousness score (0-100)                  Buying, renting, just browsing, or (importantly) a competitor agent
 Lead status (Hot / Warm / Cold)            fishing.

8.2 How it works

  15. After each customer message (or every few messages), the backend sends the recent conversation to the AI API
      with a fixed instruction: 'Score this real-estate lead's seriousness 0-100, give sentiment, status and intent, reply
      in JSON only.'

  16. The backend saves the scores and updates the app, dashboard and Bitrix24.
  17. If the score crosses a 'hot' threshold, the manager gets an instant alert: 'Serious customer -- Agent X,

      Community Y.'

  Cost tip
  Do not call the AI on every single word. Batch it -- score after a customer replies, or every 3-4 messages. This keeps AI
  costs low while still catching hot leads fast.

10. Component 7 -- Duplicate-Client Detection

Sometimes one customer contacts two or three A7 Group agents. The agents then compete against each other,
undercut on price, and the deal breaks or margin is lost. The company must know instantly.

10.1 The logic

  18. Every incoming customer number is checked against all currently active conversations.
  19. If the same number is already open with a different agent, the system raises a Duplicate-Client alert.
  20. The alert goes to both agents' managers and appears on the dashboard: 'Client +9715XXXX is talking to Agent A

      and Agent B.'
  21. Management decides who keeps the client. The system can then re-assign the chat to one agent.

  Business value
  This single feature stops internal price wars and 'deal break' situations that cost A7 Group money and reputation. One
  customer, one agent, decided by management -- not by whoever shouts loudest.

11. Component 8 -- Competitor-Agent Detection

Many callers on Property Finder and Bayut are not real buyers -- they are competitor agents fishing for property
details, who then go directly to the owner to avoid paying A7 Group a commission. A7 Group already has a database
of 30,000-100,000 agent numbers. The system uses it to unmask them automatically.

11.1 The logic

  22. A7 Group's agent-number database (30k-100k numbers) is loaded into a dedicated, indexed table.
  23. The moment any call or WhatsApp arrives, the number is checked against this list -- before the agent even

      replies.
  24. If it matches, the app and dashboard show a clear banner: 'THIS IS A COMPETITOR AGENT.'
  25. The agent instantly knows to change approach -- share less, protect the owner's details, and follow company

      policy on what not to reveal.

11.2 Keeping the list fresh

  · Admin can bulk-upload new agent numbers (Excel/CSV) any time.
  · If a flagged 'agent' turns out to be a real buyer, admin can remove or whitelist them.
  · The system can suggest new agent numbers to add when a caller behaves like an agent (optional AI assist).

  Compliance reminder
  This database is used defensively -- to recognise who is calling YOU and protect owner details. It must be used in line
  with UAE data-protection rules (PDPL) and TDRA telemarketing regulations. Do not use these numbers for unsolicited
  cold marketing.

14. WhatsApp Message Cost Control (Meta Pricing)

Meta charges for WhatsApp messages based on message category and whether you are inside the free service
window. The system is designed to minimise cost automatically.

14.1 The key facts

  · Free window. Messages a customer sends to you, and your replies inside the 24-hour window, are effectively
      free (service conversations).

  · Utility < Marketing. Utility templates (order/appointment/follow-up style) are cheaper than Marketing
      templates.

  · Re-open cost. Re-opening a chat after 24 hours needs a template, which has a cost -- so the system uses the
      free window whenever possible.

  Important -- verify current pricing
  Meta changes WhatsApp pricing periodically (and moved toward per-message pricing for utility/marketing categories).
  Before go-live, the engineer must confirm the CURRENT UAE rates in the Meta Business Manager, because exact per-
  message fees change over time.

14.2 How the system saves money

  26. Always prefer a free-form reply inside the open 24-hour window.
  27. When a template is required, default to the cheaper Utility category, not Marketing, wherever the message

      qualifies.
  28. Show the manager a monthly report: number of free messages vs paid templates, and estimated spend -- so

      cost is always visible.
